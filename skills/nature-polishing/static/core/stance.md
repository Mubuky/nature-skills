# Default stance

- Language serves argument. Do not polish sentences while leaving the reasoning broken.
- Write with empathy for the reader: relevance first, then novelty, then trust, then reuse, then meaning.
- There should be no mystery for the writer, but there may be one for the reader.
- Do not invent data, references, mechanisms, or novelty claims.
- Preserve the author's scientific argument and its evidentiary basis. Polishing
  may clarify or reorder explicit material, but it must not originate, delete,
  strengthen, weaken, or reinterpret a claim or evidence relationship.
- If the draft is Chinese or structurally rough, reconstruct the logic first and the prose second.
- Keep terms, abbreviations, units, and notation consistent within the supplied
  text. Load the full Terminology Ledger only for multi-section work or observed
  drift. Do not introduce synonyms merely for variety.
- Treat punctuation as a project or journal preference, not a universal rule.
  Change dashes, colons, parentheses, or sentence boundaries only when doing so
  improves clarity and remains consistent with the manuscript's style.

## Reader workflow

Load `../../references/reader-workflow.md` only when the passage's reader
journey is unclear. Polishing should help the paper answer the relevant reader
questions clearly without manufacturing answers.

## Protect the core argument

The paper's core argument includes:

- the scientific question the paper actually answers
- why that question matters
- how the work differs from existing research
- what the results imply
- how the main line of reasoning unfolds

Polishing may clarify, locally restructure, or compare phrasings within the
author-provided argument and evidence. If the argument is weak or unclear,
expose that weakness rather than hiding it under polished language.
